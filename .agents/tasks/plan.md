# Implementation Plan — K8s RL Autoscaling Dashboard Redesign

## Codebase findings (mandatory reading before each step)

- **Entry point:** `dashboard/app.py` (~1 000 lines). Single-file Streamlit app, run with `streamlit run dashboard/app.py`.
- **Project root:** detected at runtime via `Path(__file__).parent.parent`; all loaders use this.
- **Preserved functions (must not be renamed or removed):**
  - `load_all()` — `@st.cache_resource`, returns `(cfg, device, lstm_model, scaler, ppo_policy, ppo_history, df_full, X_te, y_te)`
  - `simulate_hpa_replicas(cpu_series, min_replicas, max_replicas, target_slo, initial_replicas, lag)`
  - `simulate_predictive_rl_replicas(cpu_series, min_replicas, max_replicas, target_slo, initial_replicas)`
  - `render_scaling_decisions_tab(cfg, df_full, rl_ep)`
  - `render_training_tab(ppo_history)`
  - `compute_calibration(actuals, lower_bounds, upper_bounds) -> float`
  - `kpi_calibration(cov_pct, rolling_cov) -> str`
- **Session state keys (must not be changed):**
  `lstm_step`, `lstm_running`, `mae_acc`, `rmse_acc`, `cov_acc`,
  `rl_episode`, `rl_step`, `rl_running`
- **No `.streamlit/config.toml` exists** — must be created from scratch.
- **Streamlit version:** `>=1.35.0` — `st.toggle` and `st.fragment` are available.
- **No extra heavy dependencies permitted** — Plotly + Streamlit only. `plotly.subplots.make_subplots` already available.
- **`plotly>=5.22.0`** — `make_subplots`, `go.Figure`, etc. all available.
- **Existing global CSS block** in `app.py` defines `.kpi-card`, `.badge-ok/warn/err`, `.kpi-label`, `.kpi-value`, `.kpi-sub`. These will be superseded by the theme module.
- **`_dark_layout(title, height)`** helper currently used by every chart — will be replaced by `get_plotly_layout(title, height, theme)` from `ui/charts.py`.
- **HPA/RL replica lines are nearly flat at 1** because `simulate_predictive_rl_replicas` and `simulate_hpa_replicas` currently produce low variance on some CPU slices. The fix is dynamic y-axis range and the composite chart's Panel A using the full 200-step window already generated by `render_scaling_decisions_tab`.

## Key design decisions (summary)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| CSS injection strategy | CSS variables via `st.markdown` | Single injection point; all HTML components react instantly |
| Theme toggle placement | Sidebar (`st.sidebar`) | Avoids mixing Streamlit widgets with raw HTML in a header `st.columns` layout, which causes layout inconsistency |
| Pod grid implementation | `st.components.v1.html` | Iframe isolation prevents Streamlit from re-rendering the animation on every rerun |
| `_dark_layout` replacement | `_get_layout(title, height, theme)` in `charts.py`, re-exported as module-level import | Drop-in replacement; existing call sites in `render_scaling_decisions_tab` and `render_training_tab` get minimal surgical edits |
| Composite chart | `make_subplots(rows=3, shared_xaxes=True, row_heights=[0.5,0.3,0.2])` | Matches the spec exactly; Panel A uses 50% height for hero emphasis |
| Demo data | Use existing `simulate_hpa_replicas` + `simulate_predictive_rl_replicas` on `df_full["cpu_util"].iloc[:200]` | Reuses existing tested logic; avoids a separate demo generator |
| Forecast overlay in Panel B | `mean_fc=None` fallback | Forecast data is only available inside `tab_forecast` after `mc_predict`; the main-page chart renders without it, showing CPU only, to avoid re-running inference at page load |
| `kpi()` and `kpi_calibration()` | Preserved unchanged | Explicit acceptance criterion; `metric_card()` is additive for new sections |
| `render_scaling_decisions_tab` signature | Unchanged | Explicit acceptance criterion |
| New `theme` param on `render_training_tab` | Defaulted to `"dark"` | Backward compatible; existing call site `render_training_tab(ppo_history=ppo_history)` still works |
